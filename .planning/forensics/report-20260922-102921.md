## Anomalias / Achados (com prioridade)

### P0-1 — UI thread-unsafe no fluxo OCR de extração — `src/ui/views/gerar_view.py:93-100`
**Evidência:** `extrair_todos` roda em `threading.Thread` (`extracao.py:44`). Na view, apenas `on_done` é repassado via `self.after(0, …)`; `on_prog` chama `prog.set()` / `lbl.configure()` e `on_err` chama `log_erro` **direto da thread worker**. CustomTkinter/Tk não é thread-safe.
**Interpretação:** atualização de widgets fora da main thread → corrida, glitch visual e crashes intermitentes. `on_prog` deve ser marshallizado por `self.after(0, ...)` assim como `on_done`.

### P0-2 — Instaladores silenciam falhas de dependência (causa raiz do bug DOCX) — `install.sh:143-148`, `install_ctk.sh:113-123`
**Evidência:** `sudo pip3 install ... 2>/dev/null || true` engole qualquer erro. `requirements.txt` não listava `lxml` (dependência de python-docx) — se o pip falhar, o app sobe com `DOCX_SUPORTADO=False` silenciosamente.
**Interpretação:** usuário vê "instalação concluída" com feature quebrada. Deve: listar `lxml` explicitamente, não suprimir stderr, verificar import pós-instalação e abortar com mensagem clara.

### P1-3 — KPI de Modelos destruídos / heurística frágil — `src/ui/views/modelo_view.py:82-101`
**Evidência:** primeiro loop destrói todo `CTkLabel` filho cujo texto é numérico ou contém "/" (destrói o próprio label de valor, ex.: "1"). Segundo loop tenta `configure(text=val)` apenas se `"24" in str(font)` — mas o label já foi destruído ou depende de string interna da fonte. `get_colors()` descartado na linha 83; `except:` pelado.
**Interpretação:** após o primeiro refresh com modelo carregado, o número de "Modelos carregados" pode sumir; atualização de KPIs é não-determinística. Exige refactor: manter referência do label de valor ou usar `font_size` de `FONTS`, não string mágica; remover loop destrutivo.

### P1-4 — `lote_fontes` fica dessincronizado ao remapear campo p/ outro doc — `src/services/mapeamento.py:17-47`
**Evidência:** `adicionar` → `_sync_lote` só atualiza a entrada cujo `documento_path` bate com o novo doc. **Interpretação:** remapeamento gera mapeamento fantasma no doc antigo (retângulo duplicado/errado). `_sync_lote` deve remover `placeholder` de todos os outros entries antes de gravar no novo.

**Interpretação:** import de mapeamento de outro doc gera estado "órfão" (rects não desenham, OCR falha silenciosamente). A API deveria validar/avisar em vez de `pass`.
